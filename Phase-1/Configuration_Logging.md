# 🛠️ Phase 1: Configuration & Logging

This document explains how **DealerConnect** is managed and monitored. We use a centralized configuration system and a standardized logging strategy to ensure the application is production-ready and easy to debug.

---

## 🏛️ 1. Centralized Control Panel

The entire behavior of the backend is controlled from a single "Source of Truth." This allows us to change database credentials, server ports, or security tokens without touching the Java code.

**Key File**: [application.properties](file:///Users/sgirishkumar/Documents/DealerConnect/backend/src/main/resources/application.properties)

| Category | Responsibility | Examples |
| :--- | :--- | :--- |
| **Database** | Connection parameters | JDBC URL, Username, Password (Lines 4-7) |
| **Server** | Port and Context Path | `server.port=8080`, `/api/v1` (Lines 16-17) |
| **JWT** | Security tokens | `jwt.secret`, `jwt.expiration` (Lines 27-28) |
| **Performance**| Compression settings | `server.compression.enabled=true` (Line 22) |

---

## 📝 2. Operational Visibility (Logging)

We use the **SLF4J** facade with **Logback** (the industry-standard) to provide real-time updates on what the app is doing.

### 🍱 Logging Levels
We have tuned our logs based on the environment to prevent "log spam" while keeping critical info visible.

- **DEBUG (Hibernate SQL)**: We log every SQL query generated by Hibernate (Line 33) to help developers optimize database performance.
- **INFO (App Logic)**: Standard operational logs (Line 31) like "Dealer Approved" or "Server Started."
- **WARN (Security)**: Logs security failures or invalid JWT tokens (Line 32) so admins can spot potential attacks.

### 🍱 Code Example
```java
@Slf4j // Lombok annotation for automatic logger generation
public class VehicleService {
    public void delete(Long id) {
        log.info("Deleting vehicle with ID: {}", id);
        // ... logic
    }
}
```

## 🩺 3. Health & Monitoring (Actuator)

For production reliability, we have enabled **Spring Boot Actuator**, which provides specialized endpoints for monitoring the "Vitals" of the app.

- **Endpoint**: `/api/v1/monitor/health` (Line 37)
- **Functions**:
    - **Health Check**: Checks if MySQL and the app are alive.
    - **Metrics**: Tracks memory usage, CPU load, and total API requests.
    - **App Info**: Displays the current version and description of the DMS (Line 42-44).

## 📍 4. Where is the Code?

| Category | Component | File Path |
| :--- | :--- | :--- |

---

### 💡 Phase 1 Configuration Summary
By using this standardized approach:
1.  **Environment Agility**: Switching from a developer's laptop to a production server only requires changing the `application.properties` file.
2.  **Zero-Guesswork Debugging**: When an error occurs, the logs provide a step-by-step trail of what led to the failure.
3.  **Proactive Monitoring**: The Actuator allows us to catch database connection issues before the users even notice.
